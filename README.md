# 285A · 波段手记

移动端优先的日线策略助手。部署地址：<https://shadow5673.github.io/Trading-Position/>。

替换原 Six Apples 仓位计算器，保留原 GitHub Pages 地址与 Git 历史。无需框架、服务器或券商密钥。

## 固定策略

`C-PARTIAL-CD5-v1`：收盘高于 MA20，MA20 高于 5 个交易日前；此前 3 日触及 MA10；收盘突破前日最高。次日开盘跳空在 ±3% 内入场。100 股整数手按现金买入，不加杠杆。

R = 1.5 × 信号日 Wilder ATR14。初始止损 P−R；P+2.5R 先卖约一半（奇数手先多卖一手，只有一手则全卖）。最高收盘达到 P+R 后，下一日起止损为 max(旧止损, P, 最高收盘−2×当前ATR)，只能上调。包括买入日最多 10 个交易日，并保留 28 自然日限制。最后清空仓位的卖出腿亏损后，暂停接下来 5 个交易日，第 6 个交易日方可恢复，仍需新信号。

## 使用

1. 设置策略账户本金和记录起始日。已有仓位请填写买入前资金，按实际日期补录。
2. 检查行情是否齐备，核对四项信号；符合时核算次日开盘范围和股数。
3. 券商实际成交后记录成交价格、日期和股数。网页不下单、不自动假设成交。
4. 每个收盘更新日线，核对下一交易日止损和持仓期限。盘中触价在券商执行。
5. 定期导出 JSON 备份；更换设备时导入。

初始 ATR 在买入记录中锁定。分批卖出不重置持仓日数。真实成交若偏离入场条件，可明确勾选记录偏离，不伪装成合规信号。

## 数据

- `data/market.json`：285A.T Yahoo 日线。包含既有回测历史。
- `data/calendar.json`：日本现货交易日历，截至 2027 年底；JPX 官方休市日。
- 页面支持逐日补录或 `date,open,high,low,close,volume` 格式 CSV，成交量为股。只接收完整收盘数据；缺日、重复、错误高低价会拒绝。
- `update-market.yml` 在日本时间工作日 16:20/18:20 尝试刷新。Yahoo 访问失败、历史价格变化、拆股、数据缺失时失败关闭，不用错误数据覆盖旧文件。GitHub 定时任务可能延迟、停用或遇到访问限制；页面会以真实日期提示过期，仍可手工补录。
- 自动更新提交后显式请求原 GitHub Pages 分支构建；需要仓库 Actions 的 contents/pages 写权限以及原有 Pages 配置。不会创建新的域名。

## 隐私

本金、真实交易、手工补录仅在本浏览器 `localStorage`（`swingDesk.285A.v1`）保存，不上传 GitHub 或任何后台，无统计脚本。不同设备不自动同步。静态页面请求只读取公开资源。JSON 备份包含资金与成交，请自行保管。

旧页面的存储键 `positionManagerData` 不读取、不迁移，也不主动删除。

```sh
python3 scripts/update_market.py --dry-run
```

核心计算 `strategy.js` 与界面 `script.js` 分离。测试包括与原 Python 引擎的全量历史均线、ATR、信号、成交账户对账；交易日、暂停期限、分批股数、止损次日生效、过期数据、缺日及无效成交。

`tests/reference.json` 是模拟回测的固定测试夹具，不是用户真实账户记录。

## 限制

不是券商交易终端；价格触发需要在券商执行。页面给出理论参考价格，实际挂单按券商报价单位核对。跳空与涨跌停可能无法按止损价成交。行情依赖外部源和人工输入，不保证实时。实际账户按记录成交价计算，未自动处理税款、融资费用、分红或外部出入金。增加/提取资金需要先核对账本，不能当作交易盈利。交易日历到期需要更新。

历史回测反复用同一股票样本选择规则，不能证明未来收益或回撤上限。
